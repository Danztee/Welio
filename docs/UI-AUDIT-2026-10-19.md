# UI consistency audit — 19 October 2026

Reviewed the running UI at 1440px and 375px using an isolated database, API,
and Next.js test build. Coverage: overview, appointments, customers, services,
team, members, notifications, time off, receptionist, all five settings sections,
onboarding, sign-in, sign-up, password recovery, and pending verification.

## Fixes

- One server-backed search in each paginated table; removed duplicate page-local
  search. Counts and navigation now live in table footers.
- Appointment filters use a responsive layout with readable status labels and
  full-width date fields on phones.
- Shared tables align toolbar, row and footer gutters, use readable body text,
  and mute headers. Page/panel actions stack below titles on small screens.
- Settings uses a compact section selector on mobile; desktop keeps its sidebar.
  Form spacing, session rows, and onboarding actions follow the same layout rules.
- Setup descriptions have associated IDs; decorative empty-state icons are hidden
  from assistive technology; navigation links have larger touch targets.
- Business logo picker no longer causes page overflow: the visually hidden styled
  input extended beyond the viewport. A hidden native picker backs the existing button.
- Auth screens share the centered white shell and verification has no decorative
  icon tile. Email verification and resend remain functional.
- Browser tests use a separate Next.js build directory, so a running development
  server does not prevent UI checks. That output is ignored by Git, Docker,
  formatting, and lint tools.

## Validation and limits

Seven browser tests passed, including navigation and overflow checks for the
screens above, plus existing session renewal, pagination and real service creation.
Five unit tests, TypeScript, ESLint, and the production build passed. Rendered
screenshots were reviewed for table layout, overview, settings, and auth.

This is a consistency and responsive-layout pass, not a WCAG certification.
Provider outages, every dialog state, and populated public booking/customer
self-service flows were not exhaustively visually audited in this pass.

## Table behavior follow-up

Full record tables use one toolbar search and one count footer, including empty
results. Search applies as the user types; date/status filters apply on change.
There is no Apply button. Customer/appointment search and appointment status run
on the backend before counts and cursor pagination. Services, team, notifications,
and time off search their returned records through the shared Grid. Overview
preview cards deliberately omit full-table controls. Settings are forms rather
than searchable record tables.

Hydration checks now capture console mismatches during dashboard navigation at
both viewport sizes. Development, production builds, and browser tests each use
a separate Next.js output directory to avoid overwriting a running dev server.
