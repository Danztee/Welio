# Real bookings

Implement the booking phase authorized by the owner: saved policies and time off, current availability, public and owner booking, customer reschedule/cancel, protected owner/customer lists, and transactional email through the selected ZeptoMail transport. Preserve the amber theme and reusable shadcn controls.

Use the existing PostgreSQL/Drizzle schema. Store UTC instants and the business time zone snapshot. Use Temporal for wall-clock conversion and reject ambiguous/nonexistent DST times. Availability includes service eligibility, working days/hours/breaks, full-day time off, notice/horizon, buffers, and occupied intervals. Serialize workspace configuration and booking transactions, and enforce non-overlap with a PostgreSQL GiST exclusion constraint over occupied intervals maintained by a database trigger. Preserve booked prices/durations across catalog edits.

Public catalog/availability responses exclude internal contacts, notes, appointments, and customers. Customer management requires a random capability delivered by email, hashed in the database; the link carries its token in a URL fragment so access logs/referrers do not receive it. Plain booking IDs never reveal contact or appointment data. Public writes use origin checks, bounded validation, persistent rate limits, idempotency keys, and optimistic versions for changes. Authenticated owner operations recheck current membership.

Create a durable email outbox inside each booking transaction. Provider failures do not roll back a booking. Process queued mail after responses, record failed delivery, and allow explicit owner retry; provide an authenticated job endpoint for recurring queue processing. No automatic retry of uncertain sends. Use the same business operations for future Bedrock/MCP tools; AI is not connected in this pass.

Move fictional public booking/management to /demo/book and /demo/booking, preserving the prototype. Test real PostgreSQL concurrent conflicts, raw SQL exclusion enforcement, cutoffs, failed reschedule preservation, idempotency, snapshots, access controls, private capability behavior, policies/time off, DST, and email failure/retry. Run existing regressions, checks, build, and an HTTP journey. Browser testing depends on Work browser availability.
